# AI through the customer's own account

Owner decision, 31 Oct 2026: Mizano uses AI **much less**, and only through the **organization's own AI account**: an API key from Claude (Anthropic), OpenAI, Google Gemini or OpenRouter, a connected OpenRouter account, or a self-hosted Ollama server that the server operator configured. The Colab-hosted Ollama tunnel goes away. AI stays advisory: it prepares drafts and suggestions, it never posts, pays or submits anything.

The CPU-only core is unchanged: ledger, AP/AR, reports, the rules-based invoice reader (PDF text layer or Tesseract plus deterministic rules) and batch approval work with no AI account at all.

## 1. Inventory and decision

## 2. Provider design

- **Port** `AiProvider` (`modules/ai/providers/`): `listModels(credential)` and `complete(credential, model, request)`; a request is a system text, user parts (`text`, `image`, `pdf`), a maximum output size and "answer with one JSON object". Adapters: `anthropic` (Messages API), `openai` (Chat Completions), `gemini` (`generateContent`), `openrouter` (OpenAI-compatible) and `ollama` (`/api/chat`). `none` is the default and has no adapter. Each adapter declares whether it takes images and PDFs; the reader sends a PDF only to providers that read PDFs and otherwise sends its text.
- **Fixed hosts.** Adapters call only `api.anthropic.com`, `api.openai.com`, `generativelanguage.googleapis.com` and `openrouter.ai`. The only configurable URL is `AI_OLLAMA_BASE_URL`, set by the **server operator** in the environment (an organization admin can choose Ollama only when the operator configured it, and never types a URL), validated at startup: `http(s)`, no credentials, no query or fragment. Redirects are never followed (a key-bearing request must not be forwarded).
- **Calls.** One gateway, `AiGatewayService.run(org, feature, request, schema)`: checks the organization's settings, opens the key, estimates the cost, then for each attempt re-reads the settings under the row lock (a revoke, key or provider change, feature switched off or lower limit stops it: `AI_SETTINGS_CHANGED` / `AI_LIMIT_REACHED`) and reserves that attempt under the locked monthly limit, calls the adapter with a timeout (60 s; 15 s for model lists), retries once only when the provider refused for load (429/5xx; that attempt is released) and never after an ambiguous failure (network, timeout, unreadable answer: the estimate stays spent), parses the first JSON object and validates it with zod. Invalid output, refusals and timeouts are a typed failure (`AI_INVALID_OUTPUT`, `AI_TIMEOUT`, `AI_PROVIDER_ERROR`, `AI_KEY_INVALID`); callers fall back to the CPU path, so a failing provider never blocks an upload.
- **Spend.** Prices per 1M tokens by model family (unknown models use a deliberately high price, so a limit fails safe); OpenRouter prices come from its model list and are stored when the model is chosen; Ollama costs 0. Before each call the gateway locks the organization's settings row, sums this month's reserved and settled usage and refuses when the estimate would cross the limit (`AI_LIMIT_REACHED`, translated, no call). After the call it settles the real token counts (or keeps the estimate when the provider reports none or the call timed out, and releases it when the provider answered with an error). Money is `Decimal`.
- **Usage log** `ai_usage`: feature, provider, model, tokens, estimated and settled cost, status, success, error code, user. Never a prompt, an answer or a document value.

## 3. Per-organization settings

`ai_settings` (one row per organization): provider, model, sealed key (AES-256-GCM via the shared `secret-box`, additional data `ai-key:<organizationId>`, so a ciphertext copied to another tenant fails to open), key hint (`sk-…ab12`), key source (`api_key` or `openrouter_oauth`), stored OpenRouter prices, monthly limit (default USD 5), enabled features, consent (time, user, provider) and connect/verify timestamps. `ai_oauth_states` holds OpenRouter PKCE states.

Endpoints (`/ai-settings`, JWT + `PermissionsGuard`): `GET` status and this month's usage (`settings.view`); `POST connect` (verifies the key by listing models before saving), `POST test`, `PATCH` model/limit/features, `POST consent`, `POST revoke` (destroys the ciphertext, clears model, features and consent), `POST openrouter/start` and `POST openrouter/complete` (`settings.edit`). The key is never returned; responses carry the hint only. `GET /ai-settings/features` tells any signed-in screen which features are active, nothing else.

**OpenRouter account.** `start` creates a single-use state (random 32 bytes, stored hashed, bound to the organization and the user, 10-minute expiry, PKCE verifier sealed) and returns `https://openrouter.ai/auth?callback_url=…&code_challenge=…&code_challenge_method=S256`. The callback is the web settings page on an origin from `CORS_ORIGIN`. `complete` consumes the state with a guarded update (a second use or another user/organization gets 400), exchanges the code with `POST https://openrouter.ai/api/v1/auth/keys` and saves the returned key like a pasted one.

**Personal subscriptions.** A Claude Pro/Max, ChatGPT, Codex or Gemini subscription cannot power the features that run _inside_ Mizano; those need an API key from [console.anthropic.com](https://console.anthropic.com/settings/keys), [platform.openai.com](https://platform.openai.com/api-keys), [aistudio.google.com](https://aistudio.google.com/apikey) or [openrouter.ai](https://openrouter.ai/settings/keys). The subscription works the other way round: the owner's own AI app connects to Mizano over MCP (Settings → AI → Connect your AI app, see [MCP connection](mcp-connection.md)) and works through Mizano's tools, with no key. The settings page says so.

## 4. Data and privacy rules

- Nothing leaves the server until an admin connected a provider **and** accepted the consent text that names it (Arabic and English). Switching provider clears consent and features.
- What is sent: `documents` sends the uploaded file (image or PDF) or its text layer; `categorization` adds the organization's expense-account codes and names; `summary` sends the month's P&L totals by account (no customer, vendor or document detail).
- Never logged: document text, prompts with customer data, model answers, keys or authorization headers. Logs carry organization id, feature, provider, model, sizes, durations and error codes.
- Every query is scoped by `organizationId`; a key opens only with its organization's additional data; settings writes need `settings.edit`.
- AI output stays a suggestion: the reader fills a draft for review, the account suggestion pre-selects a line account the accountant can change, the summary is labelled as AI-written.

## 5. Use AI less

- No AI scheduler loops over all organizations any more. The one scheduled AI job (summary on the 2nd) asks `AiSettingsService.organizationsUsing('summary')` first, a single indexed query, and does nothing for organizations without AI.
- The rules reader runs when AI reading is off or fails; it is not called twice when the AI answer is valid.

## 6. Migration

- `20261031030000_ai_own_accounts`: additive (`ai_settings`, `ai_usage`, `ai_oauth_states`). Retired tables and the old `organizations.ai*Enabled` flags stay, unused, until a later cleanup.
- Environment: `OLLAMA_*`, `EXTRACTION_STRATEGY`, `OLLAMA_WEBHOOK_SECRET` and the Colab tunnel are gone; `INTEGRATIONS_ENCRYPTION_KEY` (already required for FlowLine) also seals AI keys; `AI_OLLAMA_BASE_URL` is optional. `INTAKE_EXTRACTION_STRATEGY=rules` forces the CPU reader even for organizations with AI.
- Existing organizations start with AI off; nothing is sent anywhere until an admin connects and consents.

## 7. Acceptance

- With no provider connected: upload → rules draft → approval works as before; no AI screen, button or scheduler does any per-organization work.
- Connect: a wrong key is refused before saving; a good key is saved sealed and shown only as a hint; revoke destroys it.
- Reading with AI: the draft comes from the provider when its JSON is valid, from the rules reader when it is not or the call fails; the limit refuses a call that would cross it, with a translated message.
- Unit tests: adapters build the right request against a fake fetch (no network); key sealing and organization-bound AAD; no key in any response; settings permission refusal; the summary scheduler skips organizations without AI; limit reservation; OAuth state is single-use and bound to organization and user.
- Gates: full API and web unit suites, type-check (including the e2e config), lint with zero warnings, knip, jscpd at or below 2.3 %.
